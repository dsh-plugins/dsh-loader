# 2.0.0 验证记录

## 自动检查

- `npm run typecheck`：宿主与浏览器类型检查。
- `npm run build`：宿主、浏览器产物与声明文件。
- `npm test`：生命周期、配置存储与 HTTP/SSE、24 版冻结契约矩阵、UI 组件回归。
- `npm run test:package`：实际执行 `npm pack`，在仓库外的隔离目录解包；不安装 dsh，使用 `skipLibCheck: false` 检查所有公开子路径声明；再用 ABI fixture 检查八个稳定宿主子路径的 ESM/CJS 导出一致性、拒绝未知 patch、未安装解析钩子、浏览器不导入 Node 模块。此步骤不发布 npm 包。

## 真实浏览器

通过 `npm run test:browser` 启动本地配置验收页（先 build）。fixture 只使用 `.cache/browser/profile`，配置存储、桥接、EventSource 客户端及表单均使用实际实现；槽位宿主为最小实现。

2026-10-30 验证结果：

- 旧版设置入口与 `0.1.6-alpha.2` 原生入口均成功挂载，首次显示默认折叠。
- 展开后跨组 label 实测均为 126px；390px 窗口下表单没有水平溢出，数组项可编辑、增删。
- 分组使用 fieldset/legend，圆角边框在组名处自然中断；深浅主题均可读。
- 切换高级模式显示条件字段；保存后跨页面读取持久化结果。
- 输入不合法数值，宿主校验显示错误，草稿保留。
- 两个页面并发编辑：SSE 提示外部更新且不覆盖草稿；旧修订号保存被拒绝；取消修改加载最新值。

测试页不包含完整 dsh 应用壳。24 个版本均通过发布契约与启动协议检查，但未逐个启动完整 dsh 实例；该边界也记录在[版本支持表](support.md)。

## 网络插件迁移后的实际启动补验

dsh-network-settings 2.0.0 的后续验收已逐一启动 24 个完整 dsh CLI/web profile，并验证真实 HTTP 配置与出站策略；0.1.6-alpha.1 需要同版 app-boot 直接依赖固定，详见支持表。真实浏览器另验证了 0.1.5-alpha.1 聚合入口和 0.2.2-alpha.2 原生插件详情入口，均能保存；端口为 0 时宿主拒绝保存并保留草稿。

因此，上述首轮夹具验收的边界不代表后续补验未进行真实启动。原始 fixture 仍用于契约检查，实际启动使用独立安装与各自的 pnpm 解析锁。
